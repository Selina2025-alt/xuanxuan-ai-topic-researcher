# 萱萱｜AI选题研究员——Agent 使用说明书

## Agent 名称

**萱萱｜AI选题研究员**

日常称呼：**萱萱**

Hermes Profile：`topicresearchagent`

## 它是什么

这是一个面向企业 AI 落地内容的选题采集与研究 Agent。

用户给出选题领域或内容方向后，萱萱可以自动完成：

> 候选选题发现 → 来源核验 → 去重合并 → 初步筛选 → 推荐排序 → 写入选题库 → 对已采用选题开展深度研究 → 创建研究文档并回填链接。

它的职责是为后续内容创作准备可靠、完整、可追溯的选题和研究资料，不直接撰写或发布成稿。

## 省了什么人工

### 之前

人工通常需要：

1. 分别查看媒体、官网、RSS、社交平台和行业网站；
2. 逐条打开链接，确认发布时间和原始来源；
3. 判断信息真假及来源级别；
4. 合并重复报道；
5. 筛选与企业 AI 落地相关的选题；
6. 整理标题、观点、来源和时间；
7. 手动填写飞书多维表格；
8. 对采用选题继续检索并创建研究文档；
9. 把研究文档链接回填到选题库。

一次完整采集与研究，保守估算需要人工约 **3～5 小时**。

### 现在

用户只需要：

1. 在飞书中发布任务；
2. 查看萱萱给出的候选选题和推荐理由；
3. 人工确认采用、观察或淘汰；
4. 必要时指定制作日期和优先级。

萱萱负责后台采集、核验、去重、整理、入库和研究资料回填。

### 量化结果

建议使用以下口径：

> 人工投入约 180～300 分钟 → 现在人工操作及审核约 5～15 分钟。

2026 年 8 月 25 日的实际运行记录：

- Agent 后台运行时间：约 **6 分 32 秒**
- 新增候选：6 条
- 合并或去重：2 组
- 创建并回填深度研究资料：4 份
- 写入后重新读取验证：成功

这里的“6 分 32 秒”是 Agent 的实际运行时间；“5～15 分钟”是用户发布任务和审核结果所需的人力时间。不同选题范围、网络状况和研究深度会影响实际用时。

## 用了什么工具

### Codex

Codex 主要负责 Agent 的搭建和维护，包括：

- 创建、检查和修改 Hermes Profile；
- 配置飞书应用权限；
- 安装和检查外部采集能力；
- 排查网关、模型、权限和工具故障；
- 测试飞书文档、电子表格和多维表格读写；
- 维护运行配置和安全规则。

Codex 主要是“搭建者和维护者”，不是日常选题任务的主要执行入口。

### Hermes

Hermes 是萱萱的实际运行框架，负责：

- 读取 `topicresearchagent` Profile；
- 接收飞书私聊和群聊消息；
- 理解自然语言任务；
- 按 Profile 中的工作流执行多步骤任务；
- 调用搜索、网页读取和飞书工具；
- 处理任务上下文、日志和运行状态。

Hermes 真正读取的 Profile 文件是：

`~/.hermes/profiles/topicresearchagent/SOUL.md`

### 飞书 CLI

飞书 CLI 负责连接飞书业务数据，包括：

- 读取和更新选题库；
- 创建、编辑和读取飞书文档；
- 创建和编辑电子表格；
- 操作飞书多维表格的表、字段和记录；
- 创建研究资料；
- 将研究资料链接回填到选题库；
- 写入后重新读取，验证结果是否保存成功。

### 辅助采集工具

当前还会使用：

- Firecrawl：网页搜索与正文提取；
- Web Search / Web Extract：通用搜索和原始页面核验；
- RSS、AIHOT 等渠道：发现候选信息；
- 官方网站、权威媒体和专业机构：事实核验。

## 输入

### 输入 1：选题领域或内容方向

格式：自然语言。

获取方式：由用户根据账号定位、栏目方向或近期内容计划提供。

示例：

> 请采集过去24小时与企业AI落地相关的候选选题，重点关注企业采用AI或Agent、业务流程改造、组织与岗位变化、AI ToB产品、实施案例、ROI、治理安全和模型部署。

### 输入 2：筛选约束

格式：自然语言，可选。

可以包括：

- 时间范围；
- 地域范围；
- 重点公司、人物或产品；
- 目标受众；
- 内容形式；
- 重点栏目；
- 候选数量偏好；
- 排序要求；
- 是否写入选题库。

示例：

> 全球范围，优先关注微软、OpenAI、Anthropic、Google、字节跳动和企业服务公司。候选先保持“待筛选”，不要直接替我决定采用。

未指定时间时，默认优先覆盖最近 24 小时；信息不足时可扩展到最近 3 天和 7 天。

### 输入 3：人工筛选结果

格式：选题序号或母选题 ID，加上采用、观察、淘汰和排序要求。

来源：用户审核选题库或日报后提供。

示例：

> 采用序号6和8，序号6设为最高优先级；序号7先观察，其余淘汰。请保存判断理由并更新选题库。

### 输入 4：深度研究指令

格式：母选题 ID、研究方向和计划制作日期。

来源：已经确认采用的选题。

示例：

> 对 QYAI-006 开展深度研究，计划在2026年8月28日制作。请创建独立飞书研究文档，并将核心结论和文档链接回填到选题库。

原则上，完整深度研究只针对“已采用”且进入制作日前 3 天窗口的选题。

## 如何触发

### 私聊触发

在飞书中打开“萱萱｜AI选题研究员”的私聊，直接发送任务。

推荐测试提示词：

> 萱萱，请采集过去24小时与企业AI落地相关的候选选题。重点关注企业采用AI或Agent、业务流程改造、组织与岗位变化、AI ToB产品、实施案例、ROI、治理安全和模型部署。请完成信息核验、去重、筛选和排序后写入选题库。新候选先保持“待筛选”，不要开展完整深度研究。最后汇报新增数量、去重数量、推荐顺序、来源缺口和写入结果。

### 群聊触发

在已接入机器人的飞书群中，必须先 `@萱萱｜AI选题研究员`，再发送任务。

例如：

> @萱萱｜AI选题研究员 请采集过去24小时企业AI落地相关选题，核验、去重并写入选题库，完成后在群里汇报。

### 深度研究触发

满足以下任一条件后触发：

- 用户明确将选题设为“已采用”；
- 已采用选题进入计划制作日前 3 天；
- 用户明确要求提前研究。

### 定时触发

Profile 支持每日例行采集，但只有在 Hermes 中实际创建并启用定时任务后才会自动运行。

如果没有配置定时任务，仅写在 Profile 中不会自动执行。

电脑必须保持：

- 开机并登录；
- Hermes 网关正在运行；
- 接通电源；
- 机盖保持打开；
- 网络正常。

关闭飞书或 Codex 不影响 Hermes；合上机盖、关机、退出登录或断网会导致任务暂停或失败。

## 圈友怎么用

陌生人要复现这个 Agent，需要完成以下步骤：

1. 安装并配置 Hermes，确认 Hermes 实际支持的 Profile 创建方式和读取路径。
2. 只创建一个独立 Profile，例如 `topicresearchagent`。
3. 将当前 [04-Profile.md](04-Profile.md) 的内容复制到自己 Hermes 实际读取的 `SOUL.md`。
4. 将 Profile 中属于原作者电脑的绝对路径替换为自己的项目路径。
5. 在飞书开放平台创建自己的企业自建应用并启用机器人。
6. 开通消息、云文档、电子表格、多维表格和云空间所需权限。
7. 配置飞书事件订阅，使机器人能够接收私聊消息和群内 `@` 消息。
8. 使用自己的 App ID 和 App Secret 配置 Hermes 与飞书 CLI。不得复制或公开他人的密钥。
9. 创建或复制一份自己的选题库，至少包含以下字段：
   - 序号；
   - 母选题 ID；
   - 母选题；
   - 来源；
   - 内容类型；
   - 栏目系列；
   - 选题方向或核心观点；
   - 关联热点链接或帖子；
   - 原始发布时间；
   - 创建时间；
   - 选题状态；
   - 深度调研资料。
10. 在飞书云盘中准备研究资料保存文件夹，并把选题库和文件夹授权给机器人。
11. 将自己的选题库 Base URL 和研究资料文件夹位置告诉 Agent。
12. 配置搜索工具及所需 API Key，例如 Firecrawl。
13. 先进行私聊测试，再进行群聊 `@` 测试。
14. 使用前面的“推荐测试提示词”运行一轮。
15. 检查候选数量、来源、去重结果、选题状态、研究文档和回填链接，再投入正式使用。

圈友不能直接复用当前实例的 App ID、App Secret、选题库地址或本地绝对路径；必须替换成自己的配置。

## 注意事项

### 它做不了什么

萱萱不负责：

- 直接撰写完整公众号文章、视频脚本或正式成稿；
- 自动向公众号、视频平台或社交媒体发布内容；
- 制作视频、封面、海报、配图或音频；
- 在没有授权的情况下读取私人飞书文件；
- 替用户作出敏感、高风险或可能影响他人声誉的最终判断；
- 在电脑关机或睡眠时继续本地运行。

### 什么情况需要人工介入

以下情况需要用户确认：

- 最终决定采用、观察还是淘汰；
- 确认生产顺序和制作日期；
- 新增或修改选题库字段、栏目或状态；
- 多个高可信来源严重冲突；
- 单源信息长期无法核验；
- 选题涉及敏感结论或声誉风险；
- 写入状态未知或可能产生重复；
- 需要删除、覆盖或移动已有业务数据；
- 新偏好究竟是本轮临时要求还是长期规则；
- API Key、模型余额或飞书权限不足。

### 已知问题

- Firecrawl 存在请求频率限制，密集搜索时需要等待后分批重试。
- 部分关键词渠道可能返回 0 条结果，需要使用通用搜索补充。
- 飞书 CLI 的文件输入只接受当前工作目录下的相对路径。
- 批量写入曾因错误判断 API 响应而产生重复记录；当前已通过候选指纹、写后重读和只重试失败部分进行防护，但仍应核对最终数量。
- 当前没有独立的版本化 Selection Policy 文件，部分长期偏好仍依赖 Profile 默认规则和人工反馈。
- 本地运行依赖电脑持续开机、联网和保持唤醒。
- 网页来源可能出现付费墙、反爬、链接失效或只提供摘要的情况。
- 模型余额、API 配额和网络故障均可能中断任务。

### 后续改进方向

- 建立独立、可回滚的 Selection Policy 文件；
- 把 Hermes 部署到云服务器或常开设备；
- 建立稳定的每日定时采集和失败告警；
- 增加模型分级路由，简单任务使用低成本模型，复杂核验和研究使用高能力模型；
- 增加来源健康检查和备用渠道；
- 建立任务批次 ID 和更严格的幂等写入机制；
- 记录每次任务的人工审核时间、Agent 用时和 Token 成本；
- 自动统计候选采用率和重要机会覆盖率；
- 将成功截图和运行日志长期归档到项目资料目录。
