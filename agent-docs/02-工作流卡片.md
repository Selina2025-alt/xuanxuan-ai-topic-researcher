# 选题采集与研究 Agent｜工作流卡片

> 本文件只收录已确认的人工流程、判断规则和 Agent 化工作流。岗位定义以 `01-岗位卡.md` 为准。

## 一、人工原流程

1. 接收当天的选题需求，确认主题领域、重点对象、时间范围、地域范围和内容偏好；仅在需求过于宽泛、存在冲突或无法形成筛选标准时追问（3–10 分钟）。
2. 读取并应用 Selection Policy 中已有的最新版选题筛选规则，本轮不重新分析整理历史偏好（1–3 分钟）。
3. 制定本轮采集计划，确定搜索关键词、官方及一手来源、专业机构、行业作者、社区、聚合渠道和专项工具（5–10 分钟）。
4. 遍历领域必查渠道，并通过通用联网搜索和至少一种专项能力补充采集；默认覆盖最近 24 小时，必要时扩展至 3 天或 7 天。常见候选量为 5–20 条，但不设置硬上限（20–60 分钟）。
5. 逐条检查原始发布时间、链接有效性、热点信号和关键事实来源，将信息区分为已确认、媒体报道、单源报道或待补查（每条 5–12 分钟）。
6. 按“同一主体、同一事件、同一核心事实”去重并合并来源；只有出现独立结论、明显争议、新行业影响或独立内容目的时才拆题（5–20 分钟）。
7. 按三个核心方向完成初筛，并写出粗略标题、保留理由以及“选题方向/核心观点”（每条 3–8 分钟）。
8. 将候选选题写入选题库，补齐序号、母选题、发现渠道、内容类型、栏目系列、核心观点、关联链接、原始发布时间、创建时间和选题状态（每条 2–5 分钟）。
9. 完成二次筛选，将候选判断为已采用、观察或淘汰；给已采用选题分配唯一母选题 ID，并在独立排期中安排生产顺序（每批 10–30 分钟）。
10. 仅对进入制作日前 3 天窗口的已采用选题开展深度研究，形成官方或原始资料、权威讨论、背景、数据、案例和素材组成的资料包（每条 45–120 分钟）。
11. 检查核心方向是否清晰、结论是否有来源、链接是否有效、资料是否仍在 3 天时效窗口内；完成修正后回填核心观点和研究资料（每条 10–20 分钟）。
12. 汇总当日采集、筛选、研究、异常和指标，发送日报；将有效反馈立即写入 Selection Policy 并保留可回滚版本（5–15 分钟）。

## 二、关键判断点和判断依据

### 1. 需求是否足够清晰

**判断点**

- 能否提取关注话题、搜索关键词和时间范围。
- 用户已说明话题和时间时，即使范围宽泛，也直接开始广泛采集。
- 24 小时内执行过同类采集时，仍重新覆盖完整最近 24 小时，用于观察哪些信息持续靠前、热度上升。
- 近期没有执行记录且用户未说明时间时，需要确认时间范围。

**判断依据**

- 是否存在可执行的搜索关键词。
- 是否明确本轮信息时间窗口。
- 最近 24 小时是否已有同类采集记录。

### 2. Selection Policy 如何应用和进化

**判断点**

- 每轮只读取并应用最新规则，不重新整理历史偏好。
- 本轮明确要求与旧规则冲突时，本轮要求优先。
- 无法判断新偏好是临时还是全局时，必须询问用户。
- 临时偏好只作用于本轮；全局偏好立即更新 Selection Policy。
- 新旧全局规则冲突时，优先提出适用条件并让用户确认；也允许用户直接废弃旧规则。
- Agent 可以根据多轮采用、淘汰、排序、方向修改和对话反馈自主推断稳定偏好。
- 置信度高时可自动更新；拿不准时询问用户。
- 每次更新都保留历史版本，并定期反馈；质量下降时允许回滚。

**判断依据**

- 用户是否明确有效范围。
- 相似行为是否跨多轮反复出现。
- 是否能排除临时任务、时效变化等偶然因素。
- 用户修改与 Agent 判断是否长期一致。
- 更新后采用率和机会覆盖是否改善。

### 3. 渠道范围是否充分

**判断点**

- AI 任务必须覆盖既有 AI 基础渠道，再使用通用搜索和至少一种专项能力补充。
- 搜索结果开始高度重复、不再产生重要事件或独立角度时停止扩展。
- 基础渠道无法访问时，不得默默跳过，应寻找替代渠道或采集能力。
- 新能力需检查社区认可度、维护状态、口碑和安全性。当前偏好是优先采用至少约 2,000 Star 或等价高认可度的项目；认可度不足时必须先调查并隔离测试。
- 高认可度、持续维护、口碑正常且通过安全检查的能力可以自主安装。
- 长期稳定发现其他渠道遗漏信息的综合渠道可升级为基础渠道；细分能力保留为专项渠道。

**判断依据**

- 必查渠道是否全部覆盖。
- 是否同时使用通用搜索和专项能力。
- 多路结果是否高度重复。
- 新渠道的独家发现率、重复率、信息质量、更新频率和稳定性。
- 能力是否存在恶意代码、异常权限或安全差评。

### 4. 候选数量与待补查线索

**判断点**

- 5–20 条只是常见数量，不是硬上限；符合范围的信息有多少保留多少。
- 采集阶段不提前重复执行后续去重、事实核验和初筛。
- 链接打不开、正文为空、乱码或受限时，先保留为待补查线索。
- 待补查必须记录失败原因，并寻找官方来源或可信替代报道。
- 未完成核验前不得写成确定事实。

**判断依据**

- 信息是否处于用户要求的主题和时间范围。
- 当前问题属于技术性读取失败，还是信息已被证明无效。
- 是否找到同一事件的替代来源。

### 5. 候选核验做到什么程度

**判断点**

- 官方原文可以确认“官方发布或声明了什么”。
- 官方发布的产品效果、商业数据或市场结论只能视为官方自述。
- 候选阶段不提前完成深度调查；明显矛盾、重大争议或进入深度研究后再做更强交叉验证。
- 一家长期可信的权威媒体提供完整报道即可通过候选核验，但需保留“媒体报道”属性。
- 单一博主或账号的信息，如符合三个核心方向之一，可作为单源报道进入待筛选。
- 单源报道必须在核心观点中标明待核验，在链接说明中注明暂未找到独立佐证；被采用后优先补充交叉验证。
- 官方与可信媒体冲突时，如果争议本身具备热点或重要主体价值，可把争议作为选题，但必须同时呈现冲突状态。
- 长期可信来源满足“历史可溯源”或“业内高度认可”任意一项即可，兼具更好。

**判断依据**

- 是否存在官方原文或明确的一手材料。
- 内容属于客观事件，还是利益相关方自述。
- 媒体是否长期可溯源或被业内广泛引用。
- 信息状态属于已确认、媒体报道、单源报道还是待补查。
- 争议是否本身具有选题价值。

### 6. 合并还是拆分

**判断点**

- 同一主体、同一事件、同一核心事实必须合并。
- 新增细节、数据或证据不改变事件意义时继续合并。
- 新核心结论、明显冲突、新行业影响或可独立成立的内容命题可以拆分。
- 只有面向不同受众、栏目或内容目的时才值得拆分。
- 如果拆分后仍需重复大量背景和事实，应合并并在核心观点中记录多个角度。
- 未制作选题出现新进展时更新原记录、保留同一个母选题 ID，并保存旧标题、旧方向和旧来源。
- 已制作选题出现新进展时，作为新候选重新执行完整筛选。

**判断依据**

- 主体、事件和核心事实是否相同。
- 新增信息是否改变核心结论。
- 是否出现不同受众、栏目或内容目的。
- 原选题是否已经制作。

### 7. 什么选题可以进入二次筛选

**判断点**

以下三个核心方向满足任意一个即可：

1. AI 领域重要人物或头部公司的发言与动态；
2. 正在形成或持续升温的热点；
3. 企业 AI、产业 AI、AI 落地、企业转型或产品推广相关内容。

“热度足够高”满足以下任意信号即可：

- 多个独立平台、权威媒体或行业社区同时讨论；
- 重要人物、头部公司或关键利益相关方连续发声；
- 最近 24 小时至 3 天持续升温；
- 话题突破行业圈层，具有明显大众关注或账号曝光价值。

高度相关但热度较低的选题，满足以下任意条件即可保留：

- 能解释企业 AI 落地或转型中的关键问题；
- 存在稀缺案例、独家信息或信息差；
- 来自重要公司、人物或高质量研究；
- 能自然结合产品、服务或账号长期定位。

三个方向同时成立时，按“热点引入—人物或公司识别—业务关联落点”组织。标题过长时优先保留热点和重要主体，业务关联放入核心观点。高价值热点暂时找不到差异化角度时，先进入待筛选，后续继续寻找角度。

**判断依据**

- 是否符合三个方向之一。
- 是否跨平台扩散、持续升温或突破圈层。
- 是否具备长期专业价值、信息差或业务关联。
- 标题是否吸引目标用户且不造成误导。

### 8. 候选记录是否完整

**判断点**

- 候选阶段必须填写序号、母选题、所有发现渠道、内容类型、栏目系列、核心观点、至少一个关联链接、原始发布时间、创建时间和选题状态。
- 母选题 ID 只在已采用后分配。
- 深度调研资料只在完成专题研究后回填。
- 栏目暂时无法准确判断时，选择最接近的已有栏目。
- 用户点名单条栏目错误时只调整该条；用户明确说明整体不合理或用例子说明普遍问题时，再讨论栏目体系调整。
- 原始发布时间优先填写事件实际发生时间；找不到时，填写最早准确描述该事件的信息源发布时间。
- “来源”记录所有发现渠道，不记录原始发布主体；原始主体和一手资料在深度研究中补充。

**判断依据**

- 字段是否属于候选阶段必需信息。
- 是否已采用并进入深度研究。
- 用户反馈针对单条还是整体栏目体系。
- 是否能确认事件实际发生时间。

### 9. 已采用、观察、淘汰和排序

**判断点**

- 符合三个核心方向之一只是进入二筛的最低条件。
- 以下任意一项成立即可采用：
  1. 存在明确时效窗口；
  2. 能形成清晰、可讲、有吸引力的内容命题；
  3. 能获得足够资料、数据、案例或素材；
  4. 符合账号目标、排期或业务方向，且优先级更高。
- 以下任意信号可提高优先级：热度快速上升、涉及重要人物或头部公司、发布窗口很短、更容易形成业务关联或差异化内容。
- “观察”很少使用。已采用但尚未制作的选题仍保持已采用，定期复查时效后再决定是否淘汰。
- 热点或人物类选题一周内未制作时通常已经失效，应复查并淘汰。
- 长期价值选题不按固定期限淘汰，但制作前必须更新最新进展。
- 母选题 ID 是永久身份标识；生产顺序在独立排期或任务队列中维护。

**判断依据**

- 时效窗口、内容命题、资料可得性和账号目标。
- 热度上升速度、主体重要性和抢先发布价值。
- 选题属于短时效热点还是长期价值内容。

### 10. 深度研究做到多深、何时停止

**判断点**

- 只对已采用选题研究，且研究必须在计划制作日当天至提前 3 天内完成。
- 以下任意情况出现时扩展为标准研究包：重点主体或重大热点、复杂技术或行业影响、深度内容形式、最低研究包仍存在关键缺口。
- 研究核心问题可从目标受众、事件意义与影响、最终内容形式任意角度确定。
- 资料优先级为官方或原始资料、权威媒体与行业讨论、围绕关键问题扩展的背景数据案例。
- 找不到一手来源时，多家高质量媒体、专家或机构材料一致即可进入制作，不要求额外标记。
- 以下任意条件满足即可停止：核心问题得到回答、制作所需关键材料已补齐、新搜索结果大量重复且无关键增量。
- 反方材料不是完成研究的必备条件。
- 主表“选题方向/核心观点”保存关键原文、核心结论和建议讲法；独立研究资料保存完整链接及简要说明。

**判断依据**

- 选题重要度、复杂度和内容形式。
- 核心问题是否得到回答。
- 资料是否足以支撑制作。
- 新搜索是否仍产生关键增量。
- 资料距离实际制作时间是否在 3 天内。

### 11. 研究资料是否可以交付

**判断点**

以下任意问题出现时不得交付：

- 核心观点仍然模糊；
- 关键结论缺少来源、链接无效或资料不对应；
- 研究超过制作日前 3 天，或重要新进展尚未更新。

Agent 先自主补查和修正；连续补查仍失败时才请求用户协助。研究发现原核心观点不准确时直接更新并保留历史版本。核心事实不成立或无法形成原计划内容时直接淘汰，保留记录和原因，并在日报汇报。

**判断依据**

- 后续创作者能否明确知道讲什么。
- 关键结论是否有有效资料支撑。
- 研究资料是否仍然新鲜。
- 自主修正是否成功。

### 12. 日报、放权、退回和版本管理

**判断点**

日报必须同时包含：

1. 当日采集、去重、待筛选、已采用、淘汰和深度研究数量；
2. 优先制作选题及排序理由；
3. 渠道故障、待补查、核验失败、方向更新、状态变更和自动淘汰；
4. 采用率、机会覆盖、用户反馈及 Selection Policy 更新情况。

没有人工反馈时仍按时发送，并注明“暂无反馈”。

以下四项中达到任意三项，可从人工勾选切换为 Agent 自主筛选：

1. 连续多轮采用率稳定达到 70% 以上且没有明显遗漏；
2. Agent 结果与人工结果大部分一致；
3. Selection Policy 稳定并能正确处理规则冲突；
4. 影子运行结果与人工结果稳定一致。

自主模式下，以下任意情况出现即退回人工筛选：采用率持续低于 50%、连续遗漏重要机会、用户频繁撤销或重写、Selection Policy 退化且无法自主恢复。

新反馈到达后 Selection Policy 立即更新。每个版本必须同时记录更新时间和版本号、规则差异、触发证据、适用范围、更新前完整版本及回滚条件。

**判断依据**

- 采用率、机会覆盖率及人工修改频率。
- 是否遗漏重要事件。
- 影子运行与人工结果的一致度。
- 规则更新后质量是改善还是下降。

## 三、最终确认版 Agent 工作流

## Agent 工作流：选题采集与研究 Agent

### 触发条件

满足以下任意条件时开始执行：

- 用户提出选题采集需求，并给出关注话题或可提取的搜索关键词。
- 到达每日例行选题采集时间。
- 已采用选题进入计划制作日前 3 天的研究窗口。
- 收到新的采用、淘汰、排序、方向修改或对话反馈。
- 到达每日汇报时间。

### 步骤

#### 1. 解析需求并加载规则

**动作**

- Agent **MUST** 提取话题、关键词、时间范围、地域范围、重点主体和内容偏好。
- Agent **MUST** 读取最新版 Selection Policy。
- Agent **SHOULD** 保持初始采集范围足够广，不得因主题宽泛而过早收窄。

**判断**

- 话题和时间明确时 **MUST** 直接开始。
- 24 小时内已有同类采集记录时 **MAY** 默认重新覆盖完整最近 24 小时。
- 本轮明确要求与旧规则冲突时 **MUST** 以本轮要求为准。

**异常处理**

- 缺少必要时间范围且无可用默认值时 **MUST** 请求确认。
- 无法判断偏好是临时还是全局时 **MUST** 暂停规则更新并询问用户。
- Agent **MUST NOT** 将一次临时要求擅自固化为全局规则。

#### 2. 生成采集计划并配置能力

**动作**

- Agent **MUST** 建立覆盖官方主体、头部公司、代表人物、权威媒体、研究机构、专业社区、行业作者和聚合渠道的来源集合。
- AI 任务 **MUST** 覆盖既有 AI 基础渠道。
- 完成基础渠道后 **MUST** 使用通用搜索和至少一种专项能力补充。
- Agent **MAY** 发现、评估并安装新的采集能力。

**判断**

- 新能力 **MUST** 综合检查社区认可度、维护状态、口碑和安全性。
- 高认可度、持续维护、口碑正常且通过安全检查的能力 **MAY** 自主安装。
- 认可度不足但确有必要时 **MUST** 先调查并隔离测试。

**异常处理**

- 必查渠道不可访问时 **MUST** 寻找替代渠道或能力。
- Agent **MUST NOT** 使用存在恶意代码、病毒、异常权限或明显安全差评的能力。
- 无法弥补的重要渠道缺口 **MUST** 记录并向用户汇报。

#### 3. 广泛采集候选信息

**动作**

- Agent **MUST** 覆盖本轮时间与主题范围，不设置固定候选数量上限。
- 信息不足或需要判断趋势时 **SHOULD** 从 24 小时扩展到 3 天、7 天。
- Agent **MUST** 保存发现渠道、原始链接、标题、发布时间和可读取内容。

**判断**

- 超过 7 天的信息原则上作为背景。
- 超过 30 天的信息 **MUST NOT** 被当作近期热点，除非近期存在新触发。
- 多路结果高度重复且不再产生关键增量时 **SHOULD** 停止扩展。

**异常处理**

- 无法读取的内容 **MUST** 标记待补查并记录失败原因。
- Agent **MUST** 主动寻找官方或可信替代来源。
- 待补查信息 **MUST NOT** 被写成确定事实。

#### 4. 核验事实并标注状态

**动作**

- Agent **MUST** 寻找官方原文、一手材料或可信报道。
- Agent **MUST** 将信息区分为已确认、媒体报道、单源报道或待补查。

**判断**

- 官方原文可以确认官方发布行为；宣传性结论 **MUST** 标记为官方自述。
- 一家长期可信权威媒体的完整报道可以通过候选核验。
- 单源信息符合三个核心方向之一时 **MAY** 进入待筛选。
- 官方与媒体冲突时，争议具备选题价值则 **MAY** 保留为争议选题。

**异常处理**

- 单源报道 **MUST** 显著标记待核验并保留来源说明。
- 已采用的单源选题 **MUST** 在深度研究中优先补充核验；失败则观察或淘汰。
- 争议信息 **MUST** 同时呈现主要冲突说法。

#### 5. 去重、合并与拆题

**动作**

- Agent **MUST** 按同一主体、同一事件、同一核心事实识别重复并合并来源。
- 新核心结论、明显冲突、新行业影响或独立命题出现时 **MAY** 拆题。

**判断**

- 只补充细节、数据或证据时 **MUST** 合并。
- 面向不同受众、栏目或目的时 **MAY** 拆分。
- 拆分后仍需重复大量背景时 **SHOULD** 保持合并。

**异常处理**

- 未制作选题出现新进展时 **MUST** 更新原记录、保留母选题 ID 和历史版本。
- 已制作选题出现新进展时 **MUST** 作为新候选重新筛选。
- 无法判断时 **SHOULD** 优先合并；影响重大时交由人工判断。

#### 6. 执行初步筛选

**动作**

- Agent **MUST** 按重要人物或头部公司、热点、企业 AI 等重点业务方向进行筛选。
- 满足任意一个方向即可进入二筛。
- Agent **MUST** 形成粗略标题和核心观点。

**判断**

- 热点信号满足任意一项即可认定具有热度价值。
- 高度相关但低热度内容满足长期价值条件之一即可保留。
- 三个方向同时成立时 **SHOULD** 按热点引入、主体识别、业务落点组织。

**异常处理**

- 高热度但业务关联较弱时 **MAY** 为账号曝光保留。
- 暂时缺少差异化角度时 **SHOULD** 先进入待筛选。
- Agent **MUST NOT** 为关键词堆叠制造误导标题。

#### 7. 建立完整候选记录

**动作**

- Agent **MUST** 填写所有候选阶段必填字段并记录全部发现渠道。
- Agent **MUST** 优先使用事件发生时间；无法确认时使用最早准确报道时间。

**判断**

- 母选题 ID 只有已采用后才分配。
- 深度调研资料只有完成研究后才回填。
- 栏目无法准确匹配时 **MUST** 使用最接近的已有栏目。

**异常处理**

- 单条栏目错误只修改单条。
- 整体栏目不合理时 **MUST** 提出结构调整并等待人工确认。
- Agent **MUST NOT** 擅自新增或删除栏目、状态和字段。

#### 8. 执行二次筛选

**动作**

- Agent **MUST** 将候选判断为已采用、观察或淘汰。
- 前期 **MUST** 输出建议供人工勾选；自主模式下 **MAY** 独立执行。
- 已采用选题 **MUST** 分配永久唯一且不可回收的母选题 ID。

**判断**

- 时效窗口、内容命题、资料可得性、账号或业务目标满足任意一项即可采用。
- 偏离核心方向、缺乏价值、过时、重复、长期无法核验或错过窗口且无长期价值，满足任意一项即可淘汰。

**异常处理**

- 已采用但未制作的选题保持已采用并定期复查。
- 热点或人物选题一周未制作时 **SHOULD** 复查并在失效后淘汰。
- 长期价值选题 **MUST NOT** 仅因时间推移自动淘汰。
- 自动淘汰 **MUST** 保留记录和原因。

#### 9. 计算优先级并同步排期

**动作**

- Agent **MUST** 将母选题 ID 与生产顺序分离。
- Agent **MUST** 在独立排期或任务队列中维护生产顺序。

**判断**

- 热度快速上升、重要主体、短发布窗口、业务关联或差异化能力，满足任意一项即可提高优先级。

**异常处理**

- 新热点挤占排期时 **MUST** 复查被延后选题的时效。
- 失去时效且无长期价值时 **MUST** 淘汰。
- 排序变化 **MUST NOT** 修改母选题 ID。

#### 10. 在制作窗口内执行深度研究

**动作**

- Agent **MUST** 只对已采用选题开展完整研究。
- 研究 **MUST** 在制作日当天至提前 3 天内执行。
- Agent **MUST** 从目标受众、事件意义、行业影响和内容形式确定研究问题。
- Agent **MUST** 优先收集官方或原始资料，再补充权威讨论和延伸材料。

**判断**

- 重点主体、重大热点、复杂问题、深度内容形式或关键缺口满足任意一项时 **SHOULD** 扩展为标准研究包。
- 核心问题得到回答、关键材料补齐或搜索无关键增量，满足任意一项时 **MAY** 停止研究。

**异常处理**

- 找不到一手来源但多家高质量材料一致时 **MAY** 完成研究。
- 反方材料 **MAY** 收集，但不是完成研究的强制条件。
- 资料超过 3 天时 **MUST** 根据变化程度执行增量补查或完整重做。

#### 11. 生成研究资料并进行质量检查

**动作**

- Agent **MUST** 在主记录中回填精简核心结论和建议讲法。
- Agent **MUST** 在研究资料中保存完整链接、简要说明和扩展材料。
- 交付前 **MUST** 检查方向、来源、链接和时效。

**判断**

- 方向模糊、来源无效或研究过时，满足任意一项时不得交付。

**异常处理**

- Agent **MUST** 先自主补查和修正。
- 连续补查失败时 **MUST** 请求人工协助。
- 原核心观点不准确时 **MUST** 直接更新并保留历史版本。
- 核心事实不成立时 **MUST** 直接淘汰并保留原因。

#### 12. 更新偏好、评估效果并生成日报

**动作**

- Agent **MUST** 汇报数量、优先选题、异常处理、采用率、机会覆盖和 Selection Policy 变化。
- 没有反馈时 **MUST** 仍按时汇报并注明暂无反馈。
- 新反馈到达后 Selection Policy **MUST** 立即更新并保存完整版本记录。

**判断**

- 四项放权条件中至少三项成立时 **MAY** 切换为自主筛选。
- 采用率持续低于 50%、连续遗漏、用户频繁改动或规则退化，满足任意一项时 **MUST** 退回人工筛选。

**异常处理**

- 规则质量下降时 **MUST** 比较历史版本并回滚。
- 指标暂时无法计算时 **MUST** 标记数据不足，不得虚构。
- Agent **MUST NOT** 隐藏自动修改、淘汰或回滚。

## 四、成功标准

- 用户需求明确，临时偏好与全局偏好没有混淆。
- 必查来源、通用搜索和至少一种专项能力均已覆盖。
- 采集没有因为固定数量上限而提前截断。
- 重要候选的事实状态、来源、发现渠道和时效均可追溯。
- 重复事件正确合并，独立选题没有被过度拆分。
- 每条候选记录的必填字段完整。
- 已采用选题拥有永久唯一母选题 ID，生产顺序由独立排期管理。
- 热点、人物和长期价值选题按照各自时效正确排序。
- 深度研究在制作日前 3 天内完成或更新。
- 主记录能够说明“讲什么”，研究资料能够支持“怎么讲”。
- 所有自动覆盖、状态变化、淘汰和规则更新均有历史记录。
- 日报四类内容完整；没有反馈时仍按时输出。
- 候选采用率长期目标达到 70% 以上，同时持续提高重要机会覆盖率。
- 自主筛选模式至少满足四项放权条件中的三项。

## 五、失败处理

| 失败情况 | 处理方案 |
|---|---|
| 用户需求缺少话题或时间范围 | 只针对缺失的关键约束向用户追问 |
| 临时偏好与全局偏好无法区分 | 暂停规则更新并确认有效范围 |
| 新旧全局规则冲突 | 提出条件化共存方案；仍不清晰时交由用户决定 |
| 必查渠道无法访问 | 寻找替代渠道、专项能力或可信镜像，并记录覆盖缺口 |
| 新采集能力存在安全风险 | 禁止使用，改用已验证能力 |
| 搜索结果不足 | 扩展时间范围、关键词、来源类型和专项能力 |
| 搜索无法停止 | 以结果高度重复且无关键增量作为停止条件 |
| 内容无法读取 | 标记待补查、记录原因并寻找替代来源 |
| 找不到官方来源 | 使用可信权威报道或多家高质量一致材料继续核验 |
| 官方自述被误当作事实 | 降级为官方自述并修正核心观点 |
| 可信来源互相冲突 | 明确呈现争议；无选题价值时转为观察或淘汰 |
| 单源报道无法补充佐证 | 保留单源标记；被采用后优先复核，失败则淘汰 |
| 重复事件被多次建题 | 合并记录、汇总来源并保留变更历史 |
| 无法判断拆分还是合并 | 优先合并；影响重大时请求人工判断 |
| 候选必填字段缺失 | 阻止进入后续流程并自动补齐 |
| 栏目无法匹配 | 使用最接近的已有栏目，不擅自修改体系 |
| 母选题 ID 冲突 | 停止分配，修复唯一性后继续 |
| 排期变化导致热点失效 | 复查时效，失效且无长期价值则淘汰 |
| 研究资料超过 3 天 | 根据变化程度增量补查或完整重做 |
| 关键链接失效 | 寻找替代来源并更新研究资料 |
| 核心事实不成立 | 直接淘汰，保留原因和版本历史 |
| Agent 连续补查仍失败 | 暂停相关选题并请求人工协助 |
| 指标无法计算 | 标记数据不足，不生成虚假指标 |
| Selection Policy 发生漂移 | 对比历史版本、定位退化规则并回滚 |
| 自主筛选质量下降 | 自动退回人工筛选模式 |

## 六、人工兜底

以下情况必须暂停相关决策并请求人工确认：

- 无法判断新偏好是仅本次有效还是全局有效。
- 全局新旧规则冲突，Agent 提出适用条件后仍无法获得清晰边界。
- 需要新增、删除或整体调整内容类型、栏目、状态或数据结构。
- 多个高可信来源严重冲突，且错误判断可能造成重大误导。
- 选题涉及敏感、高风险或可能损害相关主体声誉的重大结论。
- 关键来源长期无法访问，替代方案不足以保证重要机会覆盖。
- 无法判断同一事件应合并还是拆分，并会显著影响后续生产。
- Agent 连续自主补查仍无法形成可交付研究包。
- Selection Policy 多次修正或回滚后仍无法恢复稳定质量。
- Agent 无法确定某项自动决策是否超出已获授权范围。
