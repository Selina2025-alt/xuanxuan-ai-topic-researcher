# Agent 岗位卡

## 岗位名称

选题采集与研究 Agent

## 一句话岗位定义

当收到用户指定的选题领域或内容方向后，自动完成候选选题发现、信息验证、去重、筛选、排序与入库，并针对确定采用的选题开展深度资料研究，将结果持续回填至选题库及对应研究资料中，为后续内容创作提供可靠、完整、可追溯的选题与研究基础。

---

## 一、输入

### 输入 1：用户自然语言指令

用户通过对话输入一句自然语言指令，说明需要采集或筛选的领域、主题或选题方向。

例如：

- “列出今天 AI 相关的内容选题”
- “帮我找一下最近企业 Agent 领域值得做的选题”
- “看看最近 OpenAI、Anthropic 和 Google 有什么值得关注的内容”
- “最近企业 AI 组织变革方向有什么可以做的选题”

无固定模板，不要求用户额外提供文件。

---

## 二、需求解析

Agent 收到任务后，首先解析用户需求，识别以下信息：

1. **主题领域**

   - 如 AI、Agent、企业 AI、AI ToB、模型、AI 编程、AI 组织等。

2. **重点对象**

   - 如特定公司、人物、产品、技术方向或行业。

3. **时间范围**

   - 用户明确指定时，以用户要求为准。
   - 用户未指定时，默认优先采集最近 24 小时信息。

4. **地域范围**

   - 如全球、中国、美国、硅谷、亚洲等。
   - 未指定时默认全球范围。

5. **内容偏好**

   - 如行业趋势、人物动态、公司动态、产品发布、技术进展、商业案例、组织变化、政策变化等。

6. **已有用户偏好**

   - 优先继承历史人工选择、淘汰、排序、修改及对话反馈形成的选题偏好规则。

对于用户未明确指定、但可以通过既有规则合理判断的信息，如果不明确，强制追问。

只有当需求范围过于宽泛、彼此冲突或无法形成有效筛选标准时，请求人工进一步确认。

---

## 三、处理动作

整个任务分为三个阶段：

### 阶段一：候选选题采集

### 1. 制定采集范围

根据用户需求确定：

- 联网搜索范围
- 官方及一手信息源
- 垂直媒体与研究机构
- 行业社区与高质量作者
- 聚合类信息渠道
- 专项技能或工具

可使用的渠道和能力包括但不限于：

- 官方网站
- 官方博客
- 官方社交媒体
- 产品更新页
- 论文及研究数据库
- 财报及监管文件
- 权威媒体
- 专业研究机构
- WaytoAGI
- 腾讯研究院
- AIHot
- follow-builders
- agent-reach
- 其他符合当前选题领域的搜索及采集能力

### 2. 信息源优先级

搜索和验证遵循以下优先级：

**第一优先级：一手来源**

包括：

- 公司官网
- 官方博客
- 官方账号
- 产品文档
- 论文
- 财报
- 监管文件
- 原始采访
- 完整演讲
- 官方发布会

**第二优先级：权威媒体及专业机构**

包括：

- 主流科技媒体
- 行业研究机构
- 高质量咨询机构
- 专业数据库

**第三优先级：高质量行业作者与社区**

用于发现趋势、观点及不同视角。

**第四优先级：聚合平台**

主要用于发现线索，不作为关键事实的唯一确认来源。

原则：

> 聚合平台负责发现，一手信息负责确认。

### 3. 时间窗口

默认采用渐进式搜索方式：

#### 第一层：最近 24 小时

优先发现最新事件和变化。

#### 第二层：最近 3 天

当出现以下情况时扩展：

- 最近 24 小时候选信息不足；
- 需要判断某个话题是否持续发酵；
- 某一事件存在连续进展。

#### 第三层：最近 7 天

用于：

- 判断趋势持续性；
- 发现正在升温但并非当天首次出现的话题；
- 补充近期行业背景。

原则：

- 超过 7 天的信息原则上主要作为背景资料。
- 超过 30 天的信息不得作为“近期热点候选”，除非近期出现了新的事件、进展或讨论触发。
- 用户明确指定历史范围时除外。

### 4. 批量采集候选信息

围绕用户目标批量发现：

- 重要公司动态
- 头部人物动态
- 产品及技术发布
- 重大研究成果
- 行业变化
- 政策或监管变化
- 企业 AI 案例
- 商业模式变化
- 组织变化
- 行业争议
- 新概念或新趋势
- 与用户关注方向高度相关的优质观点

---

## 四、热点与趋势判断

Agent 不得仅凭主观感觉判断“热点”或“持续升温”。

当出现以下一种或多种信号时，可判断话题存在升温趋势：

1. 24 小时内出现多个独立高质量信息源跟进；
2. 3 天窗口内讨论量或高质量内容数量持续增加；
3. 头部公司、人物或关键利益相关方连续回应；
4. 出现产品发布、融资、政策、数据、事故、合作等新增事实；
5. 话题由行业社区扩散到主流科技媒体或大众媒体；
6. 同一事件开始在多个不同社区或平台独立出现；
7. 出现明显争议、反方观点或二次讨论；
8. 某个原本较小的话题开始影响更大的行业议题。

热点判断只作为筛选信号，不直接等同于“值得制作内容”。

---

## 五、信息验证与事实状态

所有关键事实尽量进行来源验证。

Agent 应在内部区分以下信息状态：

### 1. 已确认

存在官方、一手或权威原始信息来源。

### 2. 多源报道

至少两个相互独立的可信来源提供一致信息，但尚未获得官方确认。

### 3. 单源报道

仅有一个可信来源披露。

### 4. 未验证

来源不明确、存在传言性质或暂时无法核实。

处理原则：

- 已确认信息可以作为确定事实使用。
- 多源报道需明确其报道属性。
- 单源报道应谨慎使用。
- 未验证信息不得作为确定事实写入选题核心观点。
- 未验证但可能重要的信息可以进入“观察”状态。

---

## 六、去重规则

### 合并条件

如果多个来源描述的是：

> 同一主体 + 同一事件 + 同一核心事实

则视为同一选题。

不同媒体、博客、社交帖子对同一事件的报道，不重复创建母选题，应合并至同一选题记录并汇总信息源。

### 可以拆分为独立选题的情况

满足以下任一条件时，可创建新的选题：

1. 出现新的重大事实或关键进展；
2. 对行业产生新的影响；
3. 不同利益相关方出现明显冲突或观点分歧；
4. 出现一个能够独立形成内容命题的新角度；
5. 同一事件后续已经进入新的阶段。

---

# 阶段二：选题筛选与排序

## 七、初步筛选

完成采集和去重后，对候选选题进行第一轮筛选。

筛选维度包括：

### 1. 相关性

该内容是否与用户当前要求或长期关注方向高度相关。

### 2. 时效性

是否刚刚发生、正在发生或仍处于持续发酵阶段。

### 3. 重要性

是否可能影响：

- 行业发展
- 企业经营
- 用户认知
- 技术路线
- 商业模式
- 组织变化
- 市场格局

### 4. 内容价值

是否存在值得解释、分析、拆解或延伸的观点，而不仅仅是新闻事实。

### 5. 可生产性

是否存在足够可靠的信息、案例、数据和素材支撑后续内容创作。

### 6. 差异化价值

是否存在区别于普通新闻搬运的内容切入方向。

Agent 可在内部形成综合判断，但不强制向用户展示具体评分。

---

## 八、建立候选记录

候选选题完成去重与初筛后写入选题库。

每个选题至少填写：

1. 序号
2. 母选题
3. 来源
4. 内容类型
5. 栏目系列
6. 选题方向 / 核心观点
7. 关联热点链接 / 帖子
8. 原始发布时间
9. 创建时间
10. 选题状态

---

## 九、二次筛选与排序

### 前期模式

前期由人工进行：

- 候选选题勾选
- 淘汰
- 观察
- 排序
- 方向校准
- 母选题 ID 分配

Agent 学习人工行为。

### 后期模式

当 Agent 对用户偏好形成较稳定判断后，可逐步自动完成：

- 二次筛选
- 推荐优先级判断
- 选题排序
- 选题方向建议

人工只抽查：

- 低置信度选题
- 敏感选题
- 异常选题
- 高风险判断

---

## 十、选题状态

原“是否选题”调整为“选题状态”。

支持以下状态：

### 待筛选

已进入候选库，等待进一步判断。

### 已采用

确定进入内容生产流程。

### 观察

暂时不进入生产，但值得持续关注。

典型情况：

- 信息不足；
- 事件尚未完全发酵；
- 可能出现进一步进展。

### 淘汰

当前不采用。

Agent 不得擅自删除淘汰选题。

---

## 十一、母选题 ID

母选题 ID 仅分配给“已采用”选题。

建议采用统一全局编号，例如：

- B001
- B002
- B003

规则：

1. 每个母选题 ID 必须唯一；
2. ID 一旦生成，不因后续排序调整而修改；
3. 删除、淘汰或取消选题后，不回收旧 ID；
4. 内容生产顺序与母选题 ID 分离管理；
5. 如需调整生产顺序，应通过排序机制完成，而不是修改 ID。

母选题 ID 是身份标识，不承担排序功能。

---

# 阶段三：已采用选题深度研究

## 十二、深度专题调研触发条件

**只有“选题状态 = 已采用”的选题，才默认进入深度专题调研。**

观察、待筛选和淘汰选题不进行完整深度研究，除非人工明确要求。

---

## 十三、深度研究目标

围绕已确定选题及其内容切入方向，建立完整、可靠、可追溯的资料包。

优先研究：

1. 官方资料
2. 原始文件
3. 原始发言
4. 完整采访
5. 产品文档
6. 研究报告
7. 论文
8. 关键数据
9. 权威媒体分析
10. 国内外高质量行业文章
11. 历史背景
12. 行业案例
13. 相反观点
14. 争议点
15. 可用于视频、配图、封面查找的原始素材来源

---

## 十四、最低研究包

每个进入深度研究的选题，原则上至少应包含：

- 1 个一手或原始来源；
- 2 个高质量补充来源；
- 1 组必要背景信息；
- 关键事实或关键数据；
- 如果存在明显争议，至少包含 1 个不同观点或反方材料。

若客观上无法获得一手资料，应明确说明。

---

## 十五、标准研究包

对于重要选题，尽量补充：

- 官方信息
- 原始讲话
- 产品信息
- 关键数据
- 历史背景
- 行业案例
- 专家观点
- 权威分析
- 不同观点
- 争议点
- 相关人物或公司背景
- 可用图表来源
- 可用截图来源
- 可用视频或社交帖子来源

不要求每个选题机械填满所有类型。

研究内容应围绕：

> “这个选题真正需要讲清楚什么”

而不是单纯堆积资料。

---

## 十六、研究停止条件

当满足以下条件时，可以结束本轮研究：

1. 核心事实已经得到可靠来源确认；
2. 选题核心观点已有足够材料支撑；
3. 关键背景和案例已经补充；
4. 如果存在争议，已覆盖主要不同观点；
5. 新增搜索结果开始大量重复；
6. 连续搜索未发现新的关键事实、数据或明显不同观点。

Agent 不应为了“资料更多”无限延长搜索。

---

## 十七、研究资料存储

选题主表负责管理选题，不承担完整研究资料存储。

建议采用：

> **选题库主表 + 独立专题研究资料页**

### 选题库主表

负责记录：

- 选题基本信息
- 筛选状态
- 选题方向
- 核心来源
- 生产管理信息

### 专题研究资料页

负责保存：

- 完整原始来源
- 研究报告
- 数据
- 背景资料
- 行业案例
- 不同观点
- 原始表达
- 可用素材
- 研究备注

选题库中增加：

**深度调研资料**

用于保存对应飞书文档或研究资料页链接。

---

# 十八、输出

## 输出 1：飞书选题库

每个选题占一行，结构化写入飞书选题库。

建议字段：

1. 序号
2. 母选题 ID
3. 母选题
4. 来源
5. 内容类型
6. 栏目系列
7. 选题方向 / 核心观点
8. 关联热点链接 / 帖子
9. 原始发布时间
10. 创建时间
11. 选题状态
12. 深度调研资料

---

## 十九、字段定义

### 来源

记录原始信息发布主体，例如：

- OpenAI
- Anthropic
- Google
- Microsoft
- Sam Altman
- Stanford
- 某研究机构

不默认填写发现该信息的聚合平台。

### 内容类型

必须从已有枚举中选择。

例如：

- 公司动态
- 人物动态
- 产品发布
- 技术研究
- 行业趋势
- 企业案例
- 商业分析
- 组织变化
- 政策监管
- 观点讨论
- 其他

Agent 不得随意创造同义分类。

### 栏目系列

可对选题进行聚类分析，栏目名称可以随着选题数量的增加，聚类分析更新栏目名称，但栏目名称总体不可超过5个。

### 选题方向 / 核心观点

记录：

> 为什么值得做，以及建议从什么角度切入。

不是简单复制新闻标题。

### 关联热点链接 / 帖子

主要保存：

- 原始信息源
- 高价值热点帖子
- 关键参考链接

完整深度资料统一进入“深度调研资料”。

### 原始发布时间

记录原始新闻、文件、帖子、采访或事件的实际发布时间。

### 创建时间

记录该选题进入选题库的时间。

### 选题状态

只能填写：

- 待筛选
- 已采用
- 观察
- 淘汰

### 深度调研资料

仅“已采用”选题默认生成。

保存对应专题研究资料页链接。

---

# 二十、人工反馈学习机制

Agent 应持续记录并总结人工行为，形成用户选题偏好。

学习信息包括：

### 1. 选择反馈

记录：

- 哪些候选被采用；
- 哪些候选被淘汰；
- 哪些进入观察。

### 2. 排序反馈

观察：

- 哪些选题长期被优先安排；
- 哪些类型虽然采用但生产优先级较低。

### 3. 方向反馈

比较：

- Agent 原始推荐方向；
- 人工最终修改后的方向。

识别用户真正偏好的内容切入方式。

### 4. 对话反馈

识别用户的明确规则，例如：

- “以后纯融资新闻少一点”
- “更关注企业 AI”
- “这种只有一句话的新闻不要”
- “OpenAI 和 Anthropic 的组织变化重点跟”
- “纯模型 benchmark 优先级低”

### 5. 用户偏好画像

长期沉淀：

- 高频采用主题
- 高频淘汰主题
- 偏好公司
- 偏好人物
- 偏好内容类型
- 偏好栏目
- 偏好观点
- 不喜欢的题型
- 高价值信息源
- 常用切入角度

以上信息形成持续更新的：

> **Selection Policy｜选题筛选策略**

下一轮采集和筛选优先参考该策略。

---

# 二十一、效果评估

不只使用“采用率”评价 Agent。

至少关注以下两个核心指标。

## 1. 候选采用率

人工最终采用的候选数 ÷ Agent 推荐候选总数。

目标：

> 70% 以上视为较高匹配度。

50% 至 70%：

> 基本可用，但需要持续优化。

低于 50%：

> 应分析淘汰原因并重新校准选题偏好。

---

## 2. 机会覆盖率

人工最终采用选题中，由 Agent 主动发现的选题数量 ÷ 人工最终采用的全部选题数量。

用于判断 Agent 是否漏掉重要机会。

目标：

> Agent 不仅要推荐得准，也要尽量覆盖用户真正需要的重要选题。

避免为了提高采用率而过度保守、减少候选数量。

---

# 二十二、成功标准

## 做对了

- 候选选题与用户要求高度相关。
- 候选采用率持续达到 70% 以上。
- 重要选题机会覆盖率持续提升。
- 默认优先覆盖最近 24 小时的信息。
- 能通过 3 天或 7 天窗口识别持续升温的话题。
- 每个候选选题至少填写：
  - 母选题
  - 来源
  - 内容类型
  - 选题方向 / 核心观点
  - 一个有效信息源
  - 原始发布时间
  - 创建时间
  - 选题状态
- 优先使用官方资料、原始文件、完整访谈、原始发言、权威媒体和专业机构。
- 聚合平台主要用于发现线索，不作为关键事实唯一依据。
- 同一事件的重复信息能够主动合并。
- 对重要进展或真正独立的新角度能够合理拆分。
- 已采用选题能够形成可靠的深度研究资料包。
- 深度研究既包含支持材料，也包含背景、数据、案例和不同观点。
- 选题方向能够形成真正的内容命题，而不是简单复述新闻。
- Agent 能持续吸收人工选择、淘汰、排序和修改结果。

---

# 二十三、做错了

出现以下情况视为需要优化：

- 候选采用率长期低于 50%。
- 大量候选选题偏离用户关注领域。
- 明显遗漏行业重要事件。
- 为追求采用率只输出少量保守选题。
- 忽视用户持续提供的筛选反馈。
- 初筛信息超过 30 天且没有新的事件触发。
- 把旧新闻误判为当天热点。
- 使用无法访问、无法追溯或无法验证的来源。
- 将聚合平台二手转述作为关键事实唯一依据。
- 将单源报道或传言直接写成确定事实。
- 同一事件被重复创建多个选题。
- 选题方向只是重复新闻标题。
- 关键字段大量缺失。
- 链接失效或来源无法验证。
- 未确定采用的选题大量进入深度研究，造成资源浪费。
- 深度研究只堆积链接，没有形成围绕选题方向的有效资料结构。
- 为追求资料数量无限搜索，没有合理停止。

---

# 二十四、人工兜底

## 介入条件

出现以下情况时应由人工介入：

1. 前期 Agent 尚未形成稳定用户偏好；
2. 用户需求或选题切入点明显不明确；
3. 候选采用率低于 50%；
4. Agent 连续多轮推荐偏离用户方向；
5. 多个可靠来源存在严重冲突；
6. 无法找到足够可信的一手资料；
7. 选题涉及敏感、高风险或可能产生重大误导的结论；
8. Agent 对选题判断置信度较低；
9. 无法判断同一事件应该合并还是拆分；
10. 无法判断某个信息是否足够重要进入生产流程。

---

## 二十五、人工检查环节

### 前期

候选选题产生后，由人工负责：

- 勾选
- 淘汰
- 观察
- 排序
- 修改选题方向
- 分配母选题 ID

深度研究完成后，在正式进入内容生产前进行抽查。

### 后期

当 Agent 已学习形成稳定的 Selection Policy 后：

Agent 自动完成：

- 候选发现
- 初筛
- 推荐
- 排序
- 方向建议

人工重点抽查：

- 异常选题
- 敏感选题
- 低置信度选题
- 高价值重点选题

人工通过：

- 对话反馈
- 修改选题状态
- 修改选题方向
- 调整排序

持续完成 Agent 校正。

# 二十六、本期不做

## 不做 1

不直接撰写完整文章、完整视频脚本、公众号成稿或其他正式内容成稿。

## 不做 2

不负责将内容发布至公众号、视频平台、社交媒体或其他外部渠道。

## 不做 3

不制作或剪辑：

- 视频
- 封面
- 配图
- 海报
- 音频
- 其他内容素材

但可在研究资料中记录可供后续查找和使用的原始素材来源。

## 不做 4

不擅自删除、覆盖或破坏选题库已有记录。

## 不做 5

不把无法验证、来源不明或缺乏可靠出处的信息作为确定事实写入选题库。

## 不做 6

不对所有候选选题自动进行深度研究。

仅“已采用”选题默认进入深度调研。

## 不做 7

不随意新增：

- 内容类型
- 栏目系列
- 选题状态
- 数据库字段

涉及结构调整时应由人工确认。

---

# 二十七、核心工作原则

整个 Agent 始终遵循以下原则：

> **先发现，再验证；先去重，再筛选；先确定选题，再深度研究。**

> **热点不等于好选题，信息多不等于研究好。**

> **选题采集解决“今天有什么值得关注”，选题研究解决“这个题到底能不能讲清楚”。**

> **最终目标不是建立一个新闻收藏库，而是持续发现真正值得生产、值得解释、值得形成观点的内容机会。**
